# 牧羊人 · 任务功能设计（评估与重新设计）

状态：设计稿，等确认后分期实现。本文回答三件事：现在缺什么、参考常见任务应用后该取什么舍什么、怎么落到牧羊人现有的结构里。

## 0. 先说结论

1. **任务和习惯不要合并成一张表，在界面层合并。** 习惯要的是“长期连续、按类型记录不同的量”（分钟、评分、服药点），任务要的是“有对象、有日期、做完就结束”。两张表各管各的，但在今天页、日历、回顾里放进同一份清单、同一套分类。
2. **新增一个“任务”页签**（今天 / 任务 / 祷告 / 回顾 / 我的 五个），今天页只保留“现在该做的”。
3. **任务有一个“时间粒度”**：日、周、月、季、年。“本季度做体检”“今年读完一遍圣经”不用硬凑一个日期，它们出现在对应的周 / 月 / 季 / 年视图里，也出现在今天页的“本周要做”里。这是满足日、周、月、季、年视图的关键，常见任务应用没有做好这一点。
4. **催促靠“让它很难被忘掉”，不靠打分和羞辱**：今日三件大事、逾期阶梯、拖了三次的任务要做决定（现在做 / 拆小 / 改期 / 放弃）、日历闹钟、晚间收尾。读经和祷告这类灵修习惯仍然不催、不打分（见第 7 节）。
5. **需要一次数据库迁移（015）**，在 Supabase SQL Editor 里手动执行，不影响现有数据；表不存在时任务页签显示“请先执行迁移 015”，其余功能照常（和现在 013 / 014 的做法一致）。

## 1. 现状评估

牧羊人现在的模型：

| 部分 | 现状 | 对任务的意义 |
|---|---|---|
| `wb_practices` | 习惯：9 种类型 + 自定义，`schedule {days, times, remind}`，`target {per, count, minutes}`，`share` | 已经是“重复的、有时间点的事”，但只能按“每周几 + 几点”重复，没有日期、没有“每月 15 号”“每季度”，也不能做一次性的事 |
| `wb_logs` | 打卡记录，`kind` 是自由文本，`practice_id` 可空 | **可以直接复用来记任务完成**（`kind = 'task'`），回顾和报表就能统一 |
| 日历订阅 | Edge Function `ics`，按钥匙生成 `.ics`，习惯按时间点进日历、到点响铃 | 任务有具体时间时可直接进同一个日历，不用装任何东西 |
| 共享 | `share = 'family'` + `family_id`，RLS 已写好，配偶只读 | 任务共享沿用同一套 |
| 今天页 | 读经 → 今日习惯 → 家人；今天页补记（`S.pick`） | 加“今日任务”一块；补记同样适用 |
| 原则 | 默认私有、不给灵修打分、按进度不按日期、提醒交给手机日历、少记一点 | 任务功能要和这些原则相容，见第 7 节 |

缺口：没有一次性事项、没有日期、没有分类、没有重复规则（月 / 季 / 年）、没有优先级、没有逾期概念、没有和他人一起做的事、没有计划视图和任务报表。

## 2. 参考产品与取舍

| 产品 | 值得学的 | 不学的 / 改造 |
|---|---|---|
| Todoist | 一句话快速添加（“明天 9 点 给妈妈打电话 #家庭 !1”）、收件箱、“今天 / 即将”两个核心视图、重复规则（“每月 15 号”“完成后 3 天”） | 项目层级太自由，容易乱。这里固定“大类 → 小类”两层 |
| TickTick | 日 / 周 / 月 / 年视图、艾森豪威尔四象限、番茄钟与任务绑定、习惯和任务同在一个 app | 功能面太大。四象限放后期，番茄钟直接复用现有 `focus.js` |
| Things 3 | “今天 / 即将 / 随时 / 某天”的少量固定视图、晚上收尾的节奏、界面克制 | 不学它的“某天（无日期）”，用时间粒度（本周 / 本月…）代替，更接近“季度、年度”的需求 |
| Microsoft To Do / Google Tasks | 我的一天、简单的子任务、和日历并排显示 | 功能少，作为“最小可用”的下限 |
| Sunsama / Motion | **今日容量**（把当天要做的任务估时加起来，超过可用时间就提示）、晨间计划、晚间复盘、把任务拖进时间块 | 不做自动排程（Motion）：不透明，也容易让人被日程牵着走 |
| Streaks / Habitica | 习惯连续、游戏化 | 不学游戏化和惩罚：和“不给灵修打分”冲突 |
| Google Calendar / 手机日历 | 到点响铃、共享日程、忙碌 / 详情两种可见度 | 不自建日历 UI 去替代手机日历，用 `.ics` 订阅联动；共享时提供“只显示忙碌” |

取舍原则：**一份清单讲清“现在做什么”**（Things 的克制），**重复和时间粒度要够用**（Todoist + 本项目的季 / 年需求），**催办靠机制不靠功能堆叠**（Sunsama 的容量和复盘），**日历交给手机**（现有 ics）。

## 3. 概念模型

### 3.1 三种东西，一份清单

| 类型 | 表 | 一句话 | 例子 |
|---|---|---|---|
| 习惯 | `wb_practices` + `wb_logs` | 长期重复、要连续和趋势 | 读经、每日锻炼、服药 |
| 任务 | `wb_tasks`（新） | 有日期或时间粒度、做完就结束，可重复 | 给张姐打电话、本季度做体检、每月 15 号交房租 |
| 事件 | `wb_tasks`，`kind = 'event'` | 有开始时间和时长，主要是占用时间 | 周六 3 点去李家拜访、周三 7 点小组聚会 |

任务和事件同一张表，事件只是“必须有开始时间和时长、完成按钮换成‘去了 / 没去’”的任务，这样日历、共享、重复都只做一遍。

**怎么选习惯还是任务**（界面里一句话提示）：要看连续天数和长期趋势 → 习惯；有明确日期或对象、做完就结束 → 任务；想要具体时间、子步骤或和家人一起 → 任务（可重复）。每日锻炼默认放习惯；想固定到“周六早上 8 点和 XX 一起跑”就建一个重复事件。提供两个转换：习惯 → 重复任务、重复任务 → 习惯。

### 3.2 分类：大类 → 小类

默认种子（可改名、加、删、排序、选颜色，存在 `wb_profile.settings.taskCats`，不另建表）：

| 大类 | 小类（默认） |
|---|---|
| 属灵 | 读经祷告、服事、聚会、门徒 |
| 家庭 | 配偶、孩子、父母、亲友探访 |
| 身体 | 锻炼、饮食、就医体检、睡眠 |
| 工作 | 项目、会议、学习进修 |
| 家务 | 采购、维修、财务账单、整理 |
| 个人 | 阅读、兴趣、休息 |
| 收件箱 | （未分类，先记下来再整理） |

习惯按种类映射到大类（读经 / 祷告 → 属灵，锻炼 / 饮食 / 睡眠 / 用药 → 身体，专注 / 屏幕 → 个人，自定义 → 可选），报表里习惯和任务就能放在同一张图里看。

### 3.3 时间粒度（period）

| period | 含义 | 到期日 | 出现在 |
|---|---|---|---|
| day | 某一天，可带具体时间 | 那一天 | 日、周、月视图；今天页 |
| week | 本周内任意一天做 | 周日 | 周视图；今天页“本周要做” |
| month | 本月内 | 月末 | 月视图；今天页“本月要做”（只在最后一周显眼提示） |
| quarter | 本季度内 | 季末 | 季视图 |
| year | 本年度内 | 12 月 31 日 | 年视图 |

粗粒度任务可以在合适的时候“落到某一天”（拖到某天 / 点“排到今天”）。逾期的定义也按粒度：周任务过了周日才算逾期。

### 3.4 重复

重复规则 `recur`：`{ freq: 'day'|'week'|'month'|'year', every: 1, days: [1,3], mday: 15, until: '2027-01-01', after: false }`。

- 固定节奏（`after: false`）：每周一三五、每月 15 号、每季度第一天（`freq: month, every: 3`）。
- 完成后重复（`after: true`）：“洗车，做完后隔 14 天再做”，按完成日起算，不会因为拖了而连环逾期。
- 做法：重复任务是**一条主记录**。完成时写一条 `wb_logs`（`kind = 'task'`，带那次的到期日），再把主记录的到期日推到下一次。不预先生成一堆未来实例，所以数据量小、改规则不用清理，历史完全在 `wb_logs` 里，报表照常。
- 日历：`recur` 直接映射成 `.ics` 的 `RRULE`。

### 3.5 其他字段

标题、备注、大类 / 小类、优先级（无 / 低 / 中 / 高，高 = 今日三件大事候选）、预估分钟（今日容量用）、子任务清单（勾选，不再嵌套）、提醒（提前几分钟，可多个）、顺延次数 `slips`（催办用）、关联习惯 `practice_id`（可空）、共享方式和“一起做的人”。

## 4. 页面设计

### 4.1 底部页签：今天 / **任务** / 祷告 / 回顾 / 我的

**今天页**（保持“现在该做什么”，不变成第二个任务页）：

1. 催办条（有逾期或马上到点才出现，见 5.1）
2. 今日三件大事（可空，早上选）
3. 今日任务（逾期的排最前，然后按时间，再是无时间的；本周 / 本月要做的折叠在底部一行）
4. 读经（原样）
5. 今日习惯（原样）
6. 家人（原样；任务共享后这里也显示“一起的事”）

今天页的补记（`S.pick`）对任务同样生效：切到前几天，可以勾“那天做了的任务”。

**任务页**，顶部四个分段：

| 分段 | 内容 |
|---|---|
| 计划 | 右上一个范围选择：日 / 周 / 月 / 季 / 年（下表） |
| 清单 | 按“大类 → 小类”折叠的树，每层带未完成数；筛选：状态、优先级、共享；搜索；收件箱在最上面，一键“整理”（逐条选大类和日期） |
| 报表 | 见 4.3 |
| 已完成 | 最近完成的，带“撤销”和“再来一次” |

计划页的五个范围：

| 范围 | 画什么 |
|---|---|
| 日 | 时间轴（6:00–23:00，每小时一行，事件和有时间的任务占位）+ 上方“全天 / 无时间”区；点空格子快速添加；未排时间的任务可点“排到 X 点” |
| 周 | 7 天，每天一块：当天条数、有没有逾期、事件时间；手机上纵向排列，点开展开；本周粒度的任务在最上面 |
| 月 | 月历：每天一排彩点（按大类着色）和数字，点一天看当天；本月粒度的任务在下面 |
| 季 | 三个月各一块：任务数、完成率；本季度粒度的任务；各大类完成进度条 |
| 年 | 12 个月的条（完成 / 未完成）；本年度粒度的任务；各大类全年完成数 |

**新增 / 编辑任务**（一个表单页，和现有习惯表单同风格）：标题必填；一行快速语法（“明天 9 点 给妈妈打电话 #家庭 !高”解析成字段，解析不了就当标题）；日期 / 时间 / 粒度；重复；大类小类；优先级；预估分钟；提醒；共享；备注和子任务折叠在“更多”里。**默认只填标题就能保存**，其余都有合理默认（进收件箱、今天）。

### 4.2 日历联动

- 有开始时间的任务 / 事件，进现有的 `.ics` 订阅：事件标题前加 ☐，带提醒闹钟，重复规则原样映射；没有具体时间但有日期的，作为全天事件，早上 9 点（可设）响一次。
- 已完成的单次任务不再出现；重复任务按主记录推进。订阅链接每 4 小时刷新，所以“刚做完又响一次”最多延迟这个时间，这个限制要在界面里说明。
- 共享：设为“家人可见”的任务 / 事件，家人在自己的今天页和计划页只读看到；如果指定了“一起做的人”，那个人的 `.ics` 里也会出现（Edge Function 里加一次查询）。可见度有两档：**详情**（标题、时间、状态）和**只显示忙碌**（别人只看到“忙碌”和时间段，像日历的忙碌 / 详情）。
- 手机日历里改了时间不会写回来（订阅是单向的），这是 `.ics` 订阅的固有限制，文档里写明。

### 4.3 报表（任务 + 习惯同一套分类）

| 指标 | 图 | 说明 |
|---|---|---|
| 完成数趋势 | 柱状：按周 / 按月 | 完成了多少条，叠加大类 |
| 大类占比 | 环形 | 时间和精力花在哪（用预估分钟加权可选） |
| 按时完成率 | 数字 + 近 12 周折线 | 在到期日当天或之前完成的比例 |
| 逾期存量 | 数字 + 按大类 | 现在欠着多少、最久的几天 |
| 拖延榜 | 列表 | `slips` 最多的几条，旁边一键“拆小 / 改期 / 放弃” |
| 清零日 | 连续天数 | 当天排的任务全部处理（完成 / 放弃 / 改期都算）的连续天数——奖励“不留尾巴”，而不是“做得多” |
| 习惯 | 沿用回顾页 | 同一个页签里切换“任务 / 习惯” |

不做排名，不做和别人比较；共享出去的任务只显示完成与否。

## 5. 效率与催办：怎么让人“赶紧做”

### 5.1 催办的五层（从轻到重，每一层都能关）

| 层 | 机制 | 做法 |
|---|---|---|
| 1 看见 | 页签角标和今天页顶部催办条 | “逾期 3 · 下一件：15:00 给张姐打电话（还有 40 分钟）”；点一下直接开始 |
| 2 选择 | 今日三件大事 | 早上从候选（高优先级、逾期、今天到期）里选最多 3 件；三件做完，今天页给一句肯定的话；最多三件，防止清单变成压力 |
| 3 升级 | 逾期阶梯 | 逾期 1 天黄、2–3 天橙、4 天起红，文案从“昨天的”到“已经拖了 5 天”；同一条被顺延 3 次（`slips ≥ 3`），不再给“改明天”按钮，而是四个选项：**现在做 25 分钟（直接开专注）/ 拆成小步 / 定到具体日期和时间 / 放弃** |
| 4 响铃 | 日历闹钟 | 有时间的任务按提醒设置响铃；标记“要催”的任务再加两个：到点后 15 分钟、60 分钟（“还没做？”）。这是写在日历里的静态闹钟，靠订阅刷新来更新 |
| 5 收尾 | 晚间复盘 | 晚上（默认 21:00，可设）今天页顶部出现“今天还剩 N 件：明天做 / 本周做 / 放弃”，一键批量处理；周日晚上多一个“本周回顾”入口，看本周完成、逾期、拖延榜 |

之后的增强（需要服务器，放最后一期）：网页推送（Web Push）。它需要一个 Edge Function + 定时任务 + VAPID 密钥，iPhone 还要把网页加到主屏幕；在这之前，层 4 的日历闹钟是更可靠的“催”。

### 5.2 提高效率的做法

- **快速添加**：一句话语法；收件箱先记下来再整理，不打断手头的事（两分钟能做完的当场做）。
- **今日容量**：把今天任务的预估分钟加起来，和可用时间（设置里填，默认 6 小时）对比；超出时提示“今天排太满了，哪几件放到明天？”并列出优先级最低的。
- **批量处理**：逾期的一键“全部排到今天 / 分散到本周 / 放弃”，但每条仍可单独改。
- **番茄钟绑定**：任务上有“开始专注”，用现有 `focus.js`，完成的专注段记到这条任务上（累计分钟），也计入专注习惯。
- **模板**：“周末探访”“每月账单”这类任务组一键建立。
- **子任务**：一层清单，足够把“拆小”做完，不做多级嵌套。

## 6. 数据模型与迁移 015（草案）

`wb_tasks` 沿用 013 的守卫和 RLS 写法，完成记录复用 `wb_logs`。以下是草案，实现时在 baby-log 的 `supabase/migrations/015_shepherd_tasks.sql` 落成文件（这个目录不进 git，和 013 / 014 一样需要手动在 SQL Editor 执行）。

```sql
begin;

create table if not exists public.wb_tasks (
  user_id    uuid not null references auth.users(id) on delete cascade,
  id         text not null,
  title      text not null default '',
  note       text not null default '',
  kind       text not null default 'task' check (kind in ('task', 'event')),
  cat        text not null default 'inbox',                  -- 大类 id（内置或 settings.taskCats 自定义）
  sub        text not null default '',                       -- 小类 id
  period     text not null default 'day' check (period in ('day', 'week', 'month', 'quarter', 'year')),
  due        date,                                           -- 到期日；period ≠ day 时 = 该周期最后一天；收件箱可空
  start_time text check (start_time is null or start_time ~ '^\d{2}:\d{2}$'),
  dur        int  check (dur is null or dur between 1 and 1440),   -- 预估 / 时长（分钟）
  recur      jsonb,                                          -- {freq, every, days, mday, until, after}
  prio       int  not null default 0 check (prio between 0 and 3),
  remind     jsonb not null default '[]'::jsonb,             -- 提前几分钟的数组，如 [0, 30]
  nag        boolean not null default false,                 -- 要催：到点后再响两次
  subtasks   jsonb not null default '[]'::jsonb,             -- [{t, done}]
  status     text not null default 'open' check (status in ('open', 'done', 'dropped')),
  done_at    timestamptz,
  slips      int  not null default 0,                        -- 顺延次数
  practice_id text,                                          -- 关联习惯（可空）
  with_ids   uuid[] not null default '{}',                   -- 一起做的家人
  share      text not null default 'private' check (share in ('private', 'family')),
  share_mode text not null default 'detail' check (share_mode in ('detail', 'busy')),
  family_id  uuid references public.families(id) on delete set null,
  sort       int  not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  primary key (user_id, id)
);
create index if not exists wb_tasks_due_idx    on public.wb_tasks (user_id, status, due);
create index if not exists wb_tasks_family_idx on public.wb_tasks (family_id, due) where share = 'family';

-- 守卫：复用 wb_guard()（user_id 不可改、family_id 只能是自己的家庭、share 与 family_id 一致）
create trigger wb_tasks_guard before insert or update on public.wb_tasks for each row execute function public.wb_guard();

alter table public.wb_tasks enable row level security;
-- 读：本人；或 share = 'family' 且在同一个家庭；或被列入 with_ids
create policy wb_tasks_select on public.wb_tasks for select to authenticated
  using (user_id = auth.uid() or (share = 'family' and family_id is not null and public.is_member(family_id)) or auth.uid() = any (with_ids));
create policy wb_tasks_insert on public.wb_tasks for insert to authenticated with check (user_id = auth.uid());
create policy wb_tasks_update on public.wb_tasks for update to authenticated using (user_id = auth.uid()) with check (user_id = auth.uid());

do $$ begin alter publication supabase_realtime add table public.wb_tasks; exception when duplicate_object then null; end $$;
```

要点：

- “只显示忙碌”是在**前端和 Edge Function** 里按 `share_mode` 隐去标题（行级权限只能管行，管不了列；如果要在数据库层面保证，需要再建一个只含时间段的视图，第二期评估）。`with_ids` 列入的人能读到整行，所以“忙碌”模式不允许同时指定一起做的人。
- 完成记录写 `wb_logs`：`kind = 'task'`，`practice_id` 为空，`data = { task_id, cat, sub, title, due, prio, slips, minutes }`。013 的 `wb_logs.kind` 本来就没有白名单，不需要改约束。
- `wb_profile.settings` 新增 `taskCats`（自定义分类）、`nudge`（催办强度、晚间复盘时间、今日容量小时数）、`taskDefaults`。
- Edge Function `ics`：多查一次 `wb_tasks`（本人的未完成任务 + `with_ids` 含本人的），生成 `VEVENT`，重复规则映射 `RRULE`，`nag` 的任务加两个正偏移的 `VALARM`。

## 7. 和现有原则的冲突与化解

| 原则 | 冲突点 | 化解 |
|---|---|---|
| 默认只有自己看得到 | 任务想共享给家人 | 默认私有，和习惯一样逐项开；共享有“详情 / 只显示忙碌”；被列为“一起做”的人只读 |
| 不给灵修打分 | 逾期阶梯、清零日像在打分 | 催办**只对任务**，读经 / 祷告 / 用药等习惯仍不催；清零日奖励的是“把今天的事处理掉（包括放弃和改期）”，不奖励“做得多”；不排名、不比较；放弃一条任务不算失败 |
| 按进度不按日期 | 任务偏偏有日期 | 日期是任务自己的属性，不是习惯的；读经计划仍按进度前进。时间粒度（周 / 月 / 季 / 年）让“不一定哪天做”的事不被硬塞日期 |
| 提醒交给手机日历 | 催办需要更强的提醒 | 仍以日历闹钟为主；App 内的催办条、晚间复盘只在打开 App 时出现，不假装能后台推送；网页推送放最后一期 |
| 少记一点 | 任务字段很多 | 只填标题就能保存，其余默认值合理；高级字段折叠；不做多级子任务、不做自动排程 |

## 8. 分期路线

| 期 | 内容 | 迁移 | 验收 |
|---|---|---|---|
| 一 | 迁移 015；任务页签（今天 / 清单 / 已完成）；新增 / 编辑 / 完成 / 撤销 / 放弃 / 顺延；大类小类（默认 + 可改）；重复（固定 + 完成后）；优先级；今天页“今日任务”+ 催办条 + 逾期阶梯；今日三件大事；`.ics` 带任务与提醒；晚间收尾；今天页补记同样适用 | 015 | 一个人一天能用它管完当天的事，手机日历到点响，逾期会变色并被追问 |
